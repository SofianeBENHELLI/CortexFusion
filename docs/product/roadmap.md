### Contract and data work

Define these read capabilities during BRN-01 before choosing endpoint names:

- **Graph window:** authorized domain/group/viewport, requested abstraction level, stable node and relation identities, aggregate membership/counts, boundary links, truncation and next-level access. A macro-edge represents a set of relations, not a new semantic relation.
- **Changes and journal:** event identity, type, occurred/recorded times, object and domain references, publication/version, cause and evidence; policy/cycle/proposal/decision references where applicable. Use a stable cursor and deterministic ordering for equal timestamps.
- **Comparison context:** either an explicit event interval or two supported published states. For cross-domain views, retain the participating domain versions/publication manifests instead of inventing a global version. Fix the comparison context across paged responses; expose stale or incomplete data.
- **Metrics and trends:** separate newly published concepts, new/strengthened/weakened/archived relations, memory entries/exits and reactivations. Define units and comparable periods. Distinguish event totals from unique objects; do not count technical retries, reactivation or regrouping as creation.
- **Availability and rights:** return supported capabilities, instrumentation start/coverage and calculation time. Apply authorization to counts, groups, links, journal entries and sources. Collective observability must not expose private conversations or silently repurpose personal episode histories.

Map, journal and metrics must read the same authorized projection and period. A cross-domain relation can appear on both territories while counting once globally. An aggregate retains separate change counts instead of hiding creation and archival behind a net balance or dominant color. Layout/grouping-policy changes must not be reported as learning events.

Maintain contracts through the repository's [contract generation workflow](../../packages/contracts/README.md), including the appropriate native extension mechanism when needed. Do not hand-edit generated TypeScript. Record significant storage, indexing or grouping choices as architecture decisions. No new endpoint or lifecycle operation is claimed available by this plan.
